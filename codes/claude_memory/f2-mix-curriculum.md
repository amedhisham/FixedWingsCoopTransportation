**THE 5-MIX "not learning / high variance" DIAGNOSIS (decisive chain):**
- NOT critic-identifiability: **EV stable 0.92-0.98** (advantages CLEAN, low-noise). Ruled out.
- NOT the dlam CLIP dead-zone: **satL/satW sub-cap** (below 1). Ruled out (that dead-zone = [[f2-shear-precursor-rewards]]/overshoot term; would zero the dlam gradient if saturated).
- SO the bottleneck is the POLICY UPDATE side, not the critic. Two suspects: (A) multi-task GRADIENT CONFLICT, (B) just SLOW + high stochastic variance.
- **2-TRAJ CONFLICT PROBE** ({+x+y+z, +x+y-z} — same +x+y, only z-sign flips): they **CO-LEARN (not anti-phase)** -> NOT gradient conflict. So the 5-mix failure is BREADTH/VARIANCE + genuine off-axis slowness (RUNG-1 single +y took 150+80 iters), COMPOUNDED by batch-splitting (each traj gets ~half the per-iter gradient).
- FIX = CURRICULUM: solve ONE direction on the FULL batch first (no splitting), save, then re-add the 2nd WARM-STARTED (they co-learn -> 2nd comes up fast). **BIGGER-BATCH LEVER — CORRECTED (2026-09-10, user pushed back, I was WRONG):** I'd said "bigger batch doesn't help, EV high = low variance = wrong lever". WRONG. EV measures the CRITIC's fit (per-sample regression R^2) — it is BLIND to the POLICY-GRADIENT variance (the score-fn term, which states/tasks landed in the batch, action sampling). High EV + a NOISY policy gradient are fully consistent -> that's exactly the "trending-right-but-noisy DET_R" seen on 1-2 trajs, and 5-mix "cooked". Multi-task DILUTION (32k split K ways -> each task's gradient from 32k/K samples) IS gradient noise from poor sampling -> MORE STEPS directly reduces it. The single-traj-learns-on-32k / 5-mix-fails-on-32k evidence does NOT prove "steps don't help" — single puts all 32k on one task, 5-mix ~6.4k each (5x fewer per task). Co-learning (no conflict) means the true multi-task gradient is GOOD -> the ONLY barrier is estimating it = variance = steps help. CAVEAT: variance ~1/sqrt(N) (diminishing) -> at high K brute-force steps get costly => curriculum (100% batch on one, warm-add) is the cheaper route to the SAME root cause (per-task sample count); use both. SCALING LAW for joint: STEPS_PER_ITER ~ K * per_task_budget (hold per-task density). The ONLY no-help case = +y BLOWUP reachability (action never sampled, [[f2-axis-generalization]]) — coverage of the ACTION space, not gradient variance. (Acted on it: STEPS_PER_ITER 32k->92k for the 2-traj phase.)
