**THE BREAKTHROUGH (2026-08-26): what actually scatters the drones, measured.** Resolves the long-standing paradox "divergent w_d disturbs the drones (loop 1.1) but the load stays fine (0.036)" and shows the coord metric has been blind to the real leak the whole time. See [[f2-residual-rl-plan]], [[f2-estimation-dead-end]].

**THE MECHANISM:** 12 force DOF (4 drones x3) = range(G) 6-D [-> load] (+) null(G) 6-D [-> internal formation]. Each drone applies its OWN slice (G+_i w_d,i)_i. If the w_d,i AGREED, the assembled 12-vec would be exactly G+w = PURE range (zero null component). Because the noisy per-drone w_d,i DISAGREE, the assembled force is a PATCHWORK that is NOT G+(anything) -> it has a nonzero **null(G) component F_null = (I - G+G)F**. That F_null is a real internal force that (a) is INVISIBLE to the load (null(G) -> zero wrench) and (b) is INVISIBLE to the coord metric (coord only sums the explicit Nlambda forces, NOT this range-induced null leak), but (c) SCATTERS the drones. The load feels the ~AVERAGE of the w_d,i (deviations cancel, + it's REGULATED -> bounded 0.036); the internal formation feels the DISAGREEMENT (unregulated -> integrates -> 1.1m). Tray+ropes analogy: 4 people pull a rigid tray slightly differently -> tray (load) feels the net/average and stays put; their FORMATION (who's bunched/spread/rotated) drifts on the disagreement, unfixed by the tray.

**MEASURED (consist_cap_probe.py, base-only, DESYNC, line+quintic):**
- ||G @ F_null|| = **5e-16** (machine zero) -> the leaked force is GENUINELY null(G), load can't feel it to fp precision.
- ||F_null|| = **0.22-0.24 N** = the scatter force; it's **3-5x the coord metric (0.043-0.068)** and coord DOESN'T include it -> coord is blind to the dominant internal disturbance. ~**7% of the range command** leaks into null.
- Explicit lambda internal force is LARGE (4N) but nearly CANCELS (net=coord 0.05) -> genuinely coordinated. The scatter is the SEPARATE F_null.

**COROLLARY — the full RL story, now mechanical:** the residual learned to use **dlam (explicit nullspace)** to CANCEL F_null (right subspace!) — but each drone's cancelling dlam is computed from its OWN view -> the 4 cancellations DISAGREE -> the assembled counter-force is itself a patchwork with a **range(G) component -> leaks BACK into the load** (load 0.036->0.086). SAME mechanism in reverse: w_d disagreement leaks range->null (scatter); the dlam fix leaks null->range (load hurt). THAT is the entire coord-vs-track frontier in one sentence. WHY RL never solved it "properly": from divergent PRIVATE views there is NO clean per-drone correction — any dlam that cancels the null leak is asymmetric->leaks to load; any dw that restores agreement needs the shared TRUE w_d each drone can only ESTIMATE from its noisy delayed view. RL found the best whack-a-mole; the clean move needs AGREEMENT = info the drones structurally lack (the wall). "lambda is not the whole nullspace once there's disagreement" (user) — the clean range=load/null=lambda split only holds under agreement.

**COORD METRIC IS BAD (reinterpret all prior logs):** it measures lambda-EFFORT/balance, NOT coordination quality, and is BLIND to F_null. LOW coord (base) = lambda balanced but drones still scattered by F_null; HIGH coord (residual) = actively FIGHTING the leak (could be GOOD). So leak_w/coord_w penalties were pushing on the already-shut door (lambda) while the leak poured through the w_d window -> explains why they "did nothing."

**THE FIX — CONSISTENCY on dw, NOT dlam:** consistency target = clean-view minus noisy-view of the base's own output (act as if you saw the true shared state). PROBED which subspace (consist_cap_probe.py, r=||target||/||base||, fits cap iff r<=cap):
- **dlam* = lam_clean - lam_base: r~0.012 (TINY)** -> lambda already coordinated -> consistency-on-lambda is a NO-OP. cap_lam is NOT the limiter (fits 1000x over).
- **dw* = w_clean - w_base: r~0.081**, fits cap_w=0.2 (~99%, max 0.21 grazes). w_clean = base's clean-agent w_d = PID on TRUE state = the SAME true-w_d that refbase_split showed takes loop 1.1->0.013. So dw* is small, REACHABLE, targets the ROOT cause (kills F_null at source: agree on w_d -> patchwork collapses to pure range -> F_null->0), AND coordinates. It does NOT open-loop the load (w_clean is closed-loop on true error, unlike the refbase REFERENCE-w_d corner that exploded).
NEITHER cap is the wall -> both corrections are small; the limiter is that RL has no signal pointing at w_clean. dw-consistency LOSS supplies it.

**IMPLEMENTATION (agreed direction; LOSS not reward — user rejected reward-as-hacking, and loss is correct anyway):** why a LOSS not a reward: you HAVE the target action -> the aux loss is the exact PATHWISE gradient 2(dw*-mean), low-variance, direct; a reward is the same objective via the high-variance SCORE-FUNCTION estimator routed through GAE/critic/adv-norm/clip (= exactly the flat-advantage decay + dynamic-range steamroll channel that's been failing). Loss also less hackable (no env path to exploit; direct output regression). Add to mappo actor loss:
  L = L_ppo - ENT_COEF*ent + CONSIST_W * ||actor_mean[:, dw-slice] - stopgrad(dw*_capped)||^2
dw* = w_clean - w_base, clipped to cap_w (regress to the ACHIEVABLE correction). Target only the dw (range) head slice; leave dlam to RL. Small CONSIST_W (guide, don't dominate; it pulls toward the delay-blurred oracle). HONEST CAVEAT: dw* is an ORACLE (true-state PID); residual can only ESTIMATE it from noisy DELAYED view -> partial, DELAY-limited (the KF-wall from [[f2-estimation-dead-end]] still caps recoverable fraction). Not a free 1.1->0.013; achievable fraction is what training reveals. But even partial pulls all 4 toward a SHARED target -> coordination the current setup can't get.
