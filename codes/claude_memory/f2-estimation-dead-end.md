**THE THESIS-DECIDING EXPERIMENT (2026-08-23): estimation is NOT the lever; the residual must be robust CONTROL.** Tool = `kf_probe.py` (base only, ZERO residual; splices a per-drone KF between the noisy load view and the frozen base by overriding `env._estimates` after `_update_estimates`).

**Setup / physics of the desync:** DESYNC corrupts ONLY each drone's LOAD VIEW (`pos_noise 0.03, vel_noise 0.10, AR(1) corr 0.995`, delays [1,2,2,1] random-walking in [0,d_i]). Physically each drone reads an AprilTag on the load with its OWN camera from its OWN viewpoint on a fast system -> the four readings are GENUINELY DIFFERENT estimates, not noisy copies of one number (so R is uncalibratable / non-white / non-stationary; delay is unknown + time-varying -> can't predict-ahead by the true lag). The KF was made DELIBERATELY GENEROUS (R = true injected std, blind fixed lookahead) = a BEST-CASE upper bound on estimation.

**Result (loop dev, base only):** raw(corrupted view) ~1.1 | perfect(true load) ~0.013 | **KF 1.35–1.50 = WORSE than raw**, closes −6% to −32% of the gap (negative), and leak(coord) goes UP too (0.047->0.114). ROBUST across TWO axes: 12 KF tunings (lookahead 0/1/2 × jerk_std 0.5–20, incl. pure de-noise no-extrapolation) AND noise corr (0.995 AND 0.98). Lowering corr does NOT rescue it.

**WHY the KF HURTS (the core insight):** coordination is EMERGENT AGREEMENT — `perfect`=0.013 works ONLY because it hands EVERY drone the IDENTICAL true state -> identical replicas -> lambdas agree -> internal forces cancel. A KF is PER-DRONE and INDEPENDENT: each filters its OWN private stream toward its OWN answer -> estimates DIVERGE MORE -> more leak -> worse. The AR(1) correlation level is a RED HERRING (0.98 still fails): the killer is NOT "unfilterable noise", it's that **decentralized estimation cannot manufacture agreement** — no noise character / KF tuning produces a signal all 4 drones compute IDENTICALLY. True state = unsensable, comms = banned.

**VERDICT: estimation ≡ coordination here.** The `perfect` ceiling is unreachable BECAUSE reaching it requires all drones to agree on the estimate, which IS the coordination problem. So there is no estimator route. This KILLS the whole "reconstruct the shared load -> feed the frozen base" arch (was the leading idea for ~an hour: separation principle / learned encoder / self-as-model propagation exploiting homogeneity / attachment-geometry known-init-then-propagate) — tested in 5 min instead of built in weeks. THESIS IS SAFE: this is the clean justification FOR the RL/robust-control direction. See [[f2-residual-rl-plan]], [[f2-training-log]].

**FORWARD POINTER (the real lever):** don't make the INPUTS agree (KF failed) — make the OUTPUTS agree despite disagreeing inputs. Two RL-native levers: (1) OUTPUT-INVARIANCE / consistency: train the policy so noisy-view lambda ≈ clean-view lambda (clean view is privileged at train) -> each drone maps its private view to the SAME lambda -> agreement -> coordination, no estimation/comms. (2) SHARED-REFERENCE anchoring: the reference trajectory is the ONE signal all 4 drones hold IDENTICALLY -> lean the policy on it (feedforward/anchor) over the divergent measurement. Both are CONTROL strategies, learnable by the residual.

**FOLLOW-UP PROBES (2026-08-23) — 3 classical baselines, each hits a wall, RL owns the gap:** the ONLY signal all 4 drones hold IDENTICALLY (zero reconstruction) is the REFERENCE, so tested feeding it to the base. Tools `refbase_probe.py` (feed ref state to WHOLE local agent) + `refbase_split_probe.py` (SURGICAL: w_d MEASURED for tracking, lambda SHARED from ref/true for coordination). Results (base only, zero residual; loop / coord):
- **Feed ref to EVERYTHING** (refbase_probe): coord -> EXACTLY 0 (reference coordinates PERFECTLY — shared input -> identical w_d/G/N/lambda -> exact cancellation) BUT loop/load EXPLODE (line load flew 7.9m) because w_d=PID(ref-ref)=0-error = pure hover feedforward -> load runs OPEN-LOOP. So you CAN'T just swap the load state for the reference; you lose all feedback.
- **Surgical split** (refbase_split_probe): keeps w_d measured (load tracks, load_err ~0.035 fine, no blowup). Sharing lambda HALVES the leak (coord 0.068->0.035; residual leak = R-delay: each drone builds N from its own DELAYED R). BUT **loop is UNCHANGED at ~1.1 even with a PERFECT (true-state) shared lambda**. Airtight isolation: true_lambda vs perfect use the SAME true lambda, differ ONLY in w_d (measured vs true) -> loop 1.09 vs 0.013. So **the LOOP is 100% bottlenecked by the divergent measured w_d, NOT lambda.**

**KEY REFINEMENT of the F2 picture — TWO separate failures, TWO sources (the old memory put all "coordination" on lambda):** (1) LEAK (coord) <- lambda-divergence (sharing lambda halves it); (2) LOOP SCATTER (drones off-loiter) <- w_d-divergence: each drone's noisy view -> different G+ w_d force -> forces nearly cancel FOR THE LOAD (load_err fine) but SCATTER the individual drones off their loiter (loop 1.1). lambda quality is a RED HERRING for loop. **The classical BIND:** measured w_d -> load tracks but drones scatter (loop bad); reference w_d -> drones agree but load open-loop (load blows up). MUTUALLY EXCLUSIVE — no classical single-signal choice gives BOTH coordination AND tracking. That coord-vs-track tension is FUNDAMENTAL to the decentralized-noisy-view setting; RL's contribution is navigating it (feedback tracking + prevent the w_d scatter). Evidence RL does what classical can't: the running MAPPO pushed loop 1.1->0.60 via dw(trim wrench)+dlam. See [[f2-residual-rl-plan]].

**Training-run status when this was found:** the desired-state-obs + leak_w=0.05 cold restart (net 256,128,64) is WORKING — iter 92: loop 1.0(plateau)->0.603 [held quintic 0.55, generalizing], entropy 4.3->3.59 (finally descending = the cold-ramp resolved, as predicted), DET_R -1.4->-0.68. BUT coord(leak) ~0.348 (~7x base) — the coordination frontier persists: buying loop partly via nullspace leak. Watch whether coord keeps climbing as loop drops (trading coordination for tracking) or settles.
