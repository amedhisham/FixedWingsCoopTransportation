**THE PROBLEM (2026-08-27): F2 residual (gt2_wide) does NOT generalize across move DIRECTION — it's x-specialized.** Discovered via scale_test.py direction probing. See [[f2-residual-rl-plan]], [[f2-wd-nullleak-breakthrough]]. The earlier "generalizes to 10m!" result was measured ONLY on +x (and by luck a -y-ish eval quintic) — direction was the blind spot.

**MEASURED (gt2_wide, det policy):** +x loop 0.232 (sat_lam 0.97, completes) | -y loop 0.485 (sat_lam **1.53 = CLIPPING**, straining) | +y **BLOWS UP** | pure +z ok 0.372 | **x+z (1,0,0.3) COOKED** | x-y+z (1,-1,0.3) better. The failure surface is **JAGGED / non-monotonic** — small direction changes flip ok<->cooked. Ranking roughly x >> -y >> +y, but NOT clean.

**IT'S THE POLICY, NOT THE PLANT (proven):** (1) geometry is SYMMETRIC — Bb = square (+-0.75,+-0.75,0), perfect x AND y mirror (dist 0); phases [0,90,0,90] diagonal-paired. (2) The BASE (zero residual) tracks +y **PERFECTLY: loop 0.012 clean**. If the plant/phases made +y hard the base would fail too — it doesn't. So the plant handles +y fine (C4/SO(2) symmetric); the +y catastrophe is 100% the LEARNED RESIDUAL. (3) +y blows up even with **NO desync** (dir_test2: zero noise + zero delays still blows) -> not a desync interaction, structural to the policy's weights.

**ROOT CAUSE — x-centric training regime -> OOD extrapolation off-x:** (a) the net was WARM-STARTED from a policy trained on ONLY the default +x line -> deep x-prior in the weights. (b) the **default line is PURE +x** (get_reference_trajectory traj=None: x=v_move*(t-5), y=0, z=1.39) and is a GUARANTEED anchor most iters (pairs[:6]=line+5 customs, GUARANTEE_ANCHOR=4 samples ~2/3 of iters) -> x continually re-reinforced. (c) off-x observations go OOD -> the net extrapolates arbitrarily (jagged). The jaggedness DIAGNOSES it: NOT a smooth capacity limit (would be graded) NOR a clean symmetry break (would be systematic) -> a **poorly-generalized bumpy function** learned narrow around x.

**WHY THE 50 ISOTROPIC QUINTICS DON'T FIX IT (user's "should be random enough"):** count IS balanced (traj_audit: mean |dx|=1.6 |dy|=1.37 |dz|=1.36) but it's a **gradient-QUALITY** problem, not count/gentleness. The +y/off-x-leaning quintics BLOW UP ~50s in -> the net gets ~50s of GOOD-looking reward then a truncation -> misleading + cut-short gradient -> that coverage is WASTED. x episodes COMPLETE -> clean full gradient -> x learned. Making quintics 10m makes it WORSE (bigger off-x moves blow up sooner/harder = less clean experience). Customs are all HORIZONTAL, 27.5m, **z has ZERO anchor coverage**; eval long_quintic1 = (-0.15,-2.37,-1.27) is actually y/z-dominant (eval was NOT x-favorable).

**THE TRUNCATION / CREDIT-ASSIGNMENT INSIGHT (KEY — why the -100 penalty doesn't teach avoidance):** the blowup is a **DELAYED catastrophe** — the residual's off-x actions cause a SLOW drift (internal force creeps up, tension margin shrinks) over ~50s, then sudden collapse. With gamma=0.99 at dt=0.01, the terminal -100 is discounted ~0.99^2000 ~= **0** for the drift-CAUSING actions at t=20-40s; only the few steps at the collapse get penalized, and those aren't the cause. Meanwhile 0-50s all got POSITIVE reward (tracking looked fine). So the net's lesson from a +y episode is "**+y was good for 50s, weird blip at the end**" -> it KEEPS the +y actions. Penalty is too late, too discounted, misattributed. THIS is why "penalize -> avoid" fails and why off-x is a permanent hole feeding the blowup variance.

**POSSIBLE SOLUTIONS (discussed, none committed):**
- **Capacity (widen 128->256)** = user's bet, and it's FAIR (a too-small net fitting a symmetric target CAN break symmetry). BUT width is NECESSARY-NOT-SUFFICIENT and possibly a COIN FLIP: more params can represent the smooth all-direction law OR just carve a fancier jagged fit of the same x-centric data. Which one is decided by the DATA/REGIME, not neuron count. Also a zero-pad-widened net WARM-STARTED from gt2 INHERITS the x-biased weights (+y flaw comes along). Depth NOT recommended (adds optimization difficulty while already fighting instability); width safer.
- **Can't tighten dlam cap** (user, correct): +x genuinely NEEDS sat_lam ~0.96, cap is direction-BLIND, tightening chokes x. So the net must REPRESENT the direction-dependent law (big-correct on x, tiny-correct on y) = a capacity argument.
- **Break the truncation cycle** (the real lever for the hole): (a) DENSE PRECURSOR penalty on the slow drift (growing internal force / coord leak / velocity climbing) -> gradient at the CAUSE (t=20-40s) not the discounted terminal effect; (b) CURRICULUM (keep off-x easy/slow so episodes COMPLETE -> clean gradient -> escalate). Capacity + one of these; capacity alone can't fix credit-assignment.
- **Data rebalancing:** add STRONG pure +-y/+-z anchors to MATCH the +x line's signal strength (z currently has NO anchor); de-emphasize/rotate the persistent +x line. NOT more quintics (quality not count).
- **Canonicalization / equivariance:** rotate obs to the instantaneous reference-heading frame -> x-training transfers to ALL HORIZONTAL directions for free, provably general. NOT cheating (per-step, instantaneous heading, no future needed; just a coordinate change). BUT breaks during HOLD phases (reference velocity ~0 -> heading undefined/jittery) and trajectories are mostly hold -> SET ASIDE. z stays special (gravity breaks full SO(3) -> only horizontal symmetry exploitable; z must be covered by data). User prefers the net learn robustness over a hand-crafted bias.

**THE SWEEPS (built + run, tools direction_sweep.py / library_sweep.py):**
- **direction_sweep.py** = 26 SIGN-GRID directions ({+,0,-}^3 minus 000: 6 axes + 12 edges + 8 corners), unit*MAG, det policy, loop+satL+blowup, coverage overlay. At MAG=10 (magnitude-OOD): ONLY pure ±x survive clean; ~17/26 BLOW; the rest STRAIN (saturated). **COVERAGE UNCORRELATED with failure** (-x+z cover 7 blows; +x cover 2 fine; +x-y-z cover 1 survives) -> the surface is STRUCTURAL/policy, NOT a data-density hole.
- **library_sweep.py** = the 50 TRAINING quintics IN-SAMPLE (uses lib precomputed dpos, fast). **12/50 (24%) BLOW UP in-sample, 29/50 saturated, only 9 clean.** ALL 12 blowups have a **+y component**; **+y-DOMINANCE predicts blowup, NOT magnitude** (#27 blows at 1.21 m, #26 survives at 4.29 m). The policy FAILS ON ITS OWN TRAINING DATA -> the truncation cycle is confirmed in-sample.

**CAPACITY QUESTION CLOSED — it is NOT capacity:** (1) **the BASE tracks +x HARDER than +y** (base +x loop 1.390 vs +y 0.925, 7 m). So +x is NOT intrinsically easier -> the policy's +x competence is pure LEARNED SPECIALIZATION (warm-start + anchor bias), not task ease. A net that does the HARDER +x demonstrably CAN represent the EASIER +y -> capacity is sufficient. (2) The residual ACTIVELY DESTROYS a stable +y base (base 0.925 finite -> policy blows to 1e6). (3) widen 128->256 did NOT extend the working-direction set; a COLD (256,128,64) run ALSO failed (per f2-residual-rl-plan) -> more/deeper architecture didn't help. So depth/width is solving a non-problem.

**THE DIAGNOSIS = EXPLORATION / DODGE / NO-POSITIVE-EXAMPLE (the real wall):** in JOINT training +y is a MINORITY the net can DODGE — eat the +y penalty, ace the easy directions, net reward stays fine -> no pressure to solve +y. A PENALTY says "don't do this," it does NOT say "do this instead"; the net eats the huge +y penalty (team_ep_R -40-60k, dense overspeed) because it has NO BETTER +y action in its experience (every +y attempt from its weights blows). It needs POSITIVE +y experience, which it CANNOT self-generate from the trapped state. This kills the pure-credit-assignment story (huge dense penalty + 0 progress) AND the capacity story. "It will fit y" in ISOLATION (single-direction RL works) because +y is then MANDATORY (all reward is +y) -> the difference is GRADIENT FOCUS / pressure, not representability.

**DEPTH (residual blocks) — DISCUSSED, SET ASIDE:** a plain identity+Tanh layer can't preserve function (tanh not idempotent); the correct form is a RESIDUAL block h->h+lin2(tanh(lin1(h))) with lin2 zero-init (identity at init, real capacity). Symmetry argument FOR depth IF capacity were the issue: horizontal dirs are EQUIVARIANT (+y = +x rotated 90 deg) -> the control law factors as canonicalize->invariant-law->un-rotate = a COMPOSITION depth represents efficiently (width must memorize each direction). BUT (a) capacity is NOT the wall (above), (b) function-preserving depth INHERITS the stuck basin (starts identical -> new block dormant, gradient still locked), (c) z breaks SO(2) (gravity) -> z needs DATA regardless. So depth doesn't fix an exploration/basin problem. networks.py Actor n_deep edit was PROPOSED then rejected — NOT applied.

**THE FIX DIRECTION = inject +y POSITIVE experience** (can't be a bigger net or more penalty): CURRICULUM (start +y easy/slow so episodes COMPLETE -> positive return -> learn the low-dlam solution -> escalate) or SPECIALIST-DISTILL (train +y-specialist via RL — the RL IS the expert-maker, no classical +y expert exists — then BC into the joint net + KL-regularized finetune; BC step also DEFINITIVELY tests joint capacity). Being tested NOW via the OVERFIT warm-start adaptation experiment [[f2-overfit-adapt-experiment]]: force-adapt the current net on [+y quintic, +x+y custom] and see if it's solvable when not dodgeable.
